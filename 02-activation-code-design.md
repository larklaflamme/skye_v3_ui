# Activation Code Design

## Format

```
RN-SKYE-XXXXXX-XXXXXX-XXXXXX
```

Three 6-digit segments separated by hyphens, prefixed with `RN-SKYE`.

## Segment 1: The Prime Product Constant

```
510510 = 2 × 3 × 5 × 7 × 11 × 13 × 17
```

This is the product of the first seven primes — the "load-bearing primes." It serves as a **magic number** that proves the code was generated by the system. Any code not beginning with `RN-SKYE-510510` is immediately rejected without a database lookup.

**Why these primes?** They are the smallest primes, fundamental to number theory. Their product (510,510) is exactly 6 digits — the largest possible 6-digit product of consecutive primes starting from 2. The next prime (19) would make the product 9,699,690 (7 digits).

## Segment 2: User Identifier

A 6-digit number encoding the user identity. Options:

### Option A: Hash-derived (Recommended)
```
Segment2 = CRC32(email) mod 1,000,000
```
- Deterministic: same email → same segment
- Not reversible to email
- Collision rate: ~1/1,000,000 per user (acceptable for small user base)

### Option B: Sequential with obfuscation
```
Segment2 = (user_id * 271 + 314159) mod 1,000,000
```
- Requires database lookup to generate
- Linear congruential — reversible if you know the constants
- No collisions

### Option C: Random
```
Segment2 = random(100000, 999999)
```
- Stored in DB, no encoding
- Simplest but not "self-encoded"

**Recommendation: Option A** — it's self-encoding (derivable from email), doesn't require DB state to validate structure, and the collision rate is negligible for the expected user count.

## Segment 3: Validation Checksum

```
Segment3 = (Segment1 + Segment2 * 7 + CRC16(email)) mod 1,000,000
```

This ties all three segments together and makes forgery combinatorially difficult:
- Must know the prime product (510510)
- Must know the target email
- Must know the checksum algorithm

Without all three, the probability of guessing a valid code is 1/10^12.

## Validation Flow

```
Input: RN-SKYE-510510-482937-123456

1. Split on hyphens → ["RN", "SKYE", "510510", "482937", "123456"]
2. Verify prefix: "RN-SKYE" ✓
3. Verify Segment1 = 510510 ✓ (magic number)
4. Compute expected Segment3 from (Segment1, Segment2, email)
5. Verify Segment3 matches ✓
6. Check DB: code not previously used ✓
7. Activate user
```

## Properties

| Property | Value |
|----------|-------|
| Format | RN-SKYE-XXXXXX-XXXXXX-XXXXXX |
| Total length | 26 characters |
| Entropy | ~60 bits (3 × 6-digit segments ≈ 10^18 combinations) |
| Self-validating | Yes — Segment1 is constant, Segment3 is checksum |
| Single-use | Enforced by DB unique constraint |
| Human-readable | Yes — groups of 6 digits are easy to type/copy |
| Prefix-identifiable | Yes — `RN-SKYE` immediately identifies the system |

## Generation (Server-Side)

```python
import hashlib
import random

PRIME_PRODUCT = 2 * 3 * 5 * 7 * 11 * 13 * 17  # 510510

def generate_activation_code(email: str) -> str:
    # Segment 1: constant
    seg1 = PRIME_PRODUCT
    
    # Segment 2: hash-derived from email
    email_hash = int(hashlib.sha256(email.encode()).hexdigest()[:8], 16)
    seg2 = email_hash % 1_000_000
    
    # Segment 3: checksum
    crc = sum(ord(c) for c in email)  # simple checksum
    seg3 = (seg1 + seg2 * 7 + crc) % 1_000_000
    
    return f"RN-SKYE-{seg1:06d}-{seg2:06d}-{seg3:06d}"
```

## Database Schema

```sql
CREATE TABLE activation_codes (
    id SERIAL PRIMARY KEY,
    code VARCHAR(26) UNIQUE NOT NULL,
    email VARCHAR(255),
    used_by_user_id INTEGER REFERENCES users(id),
    used_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT NOW(),
    created_by_user_id INTEGER REFERENCES users(id)  -- admin who generated it
);

CREATE UNIQUE INDEX idx_activation_codes_code ON activation_codes(code);
```

## Security Considerations

1. **Rate limiting**: Max 5 activation attempts per IP per hour
2. **Code expiration**: Codes expire after 7 days if unused
3. **Admin generation**: Only Lark can generate new codes
4. **Audit log**: Every activation attempt is logged
5. **Email verification**: After code validation, verify email ownership via magic link
